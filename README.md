# AI NFO · NAS 视频资料工作台

在浏览器选择 NAS 视频目录，批量用 AI 整理标题、简介、分类与标签，检查草稿后将 NFO 写回视频旁边。面向 QNAP Container Station 自部署，不需要把视频先上传到网页。

后端使用 Go，前端为 HTML / CSS / JavaScript，SQLite 存储应用数据。项目处于开发阶段，不提供旧版本数据迁移。

## 已实现

- 已挂载目录浏览、相对路径输入、递归扫描（单次最多 5000 个视频）。
- 独立视频、单个剧集 / 教程两种扫描方式。支持 `S01E02`、`02-标题` 等明确数字分集；生成资料时由 AI 根据整个剧集的目录和文件名补齐缺失编号，仍无法判断时需手动填写。
- 可配置 Chat Completions 兼容接口或 Ollama。地址、模型、密钥在网页设置；不绑定特定供应商或模型。
- 基于文件名、完整相对目录（包含上层品牌 / 课程名称）、同名 `.srt` / `.vtt` / `.txt` / `.description` / `.info.json`、同目录 `README.md` / `简介.txt` / `description.txt` 生成元数据；支持 `视频名.zh.srt` 等字幕命名。
- 草稿编辑、剧集简介与分集编辑、XML 预览、批量保存、任务取消、错误信息、重启恢复提示。
- 自动获取剧集 / 单集海报：后台并发可配置为 1–8 项（默认 1），自动选择并保存，支持内嵌图片、AI 联网匹配和视频截图；也可手动选择。
- 默认不覆盖草稿或已有 NFO。明确选择覆盖 NFO 时，直接覆盖原文件。视频文件不改名、不移动、不写入。
- 访问密码、服务端密钥保存、路径范围限制、拒绝符号链接、同名不同格式冲突检测。

## QNAP 部署

运行方式：**QNAP 上的容器访问共享文件夹 → 浏览器访问 NAS 的 8787 端口**。这不是一个云端托管网页。

推荐使用下面的 **GitHub 构建 → GHCR 镜像 → QNAP 拉取** 流程。也保留后文的 NAS 本地构建方式，二选一即可。

### 方式一：GitHub 自动构建，QNAP 拉取运行

#### 1. 上传仓库并构建

将项目源码上传到 GitHub 仓库根目录，必须包含隐藏目录 `.github/workflows/docker.yml`。不要上传 `.env`、`data/` 或视频目录；应用运行时的 AI 密钥只需在 NAS 网页里设置，不需要放进 GitHub Secrets 或镜像。

工作流会自动：

1. 检查 Go 格式、运行静态检查与竞态检测测试，检查前端 JavaScript，并构建 Go 运行镜像。
2. 启动临时容器检查健康状态、页面和未登录访问保护。
3. 测试通过后，将默认分支或 `v*` 标签的镜像推送至 GHCR，包含 `linux/amd64` 和 `linux/arm64`。普通分支和 PR 只测试，不发布。

镜像地址自动从仓库名生成并转换为小写。例如仓库为 `your-name/ai-nfo`：

```text
ghcr.io/your-name/ai-nfo:latest          # 默认分支的最新成功构建
ghcr.io/your-name/ai-nfo:v1.0.0         # 推送 v1.0.0 Git 标签后生成
ghcr.io/your-name/ai-nfo:sha-完整提交SHA # 每个发布的提交都保留此标签
```

在仓库 **Actions → Test and publish container** 查看结果。也可以在默认分支上使用 **Run workflow** 手动构建。工作流使用 GitHub 自动提供的 `GITHUB_TOKEN`，并仅在发布任务授予 `packages: write`；通常无需另配发布令牌。如果组织限制 Actions 或包创建权限，需要由仓库 / 组织管理员放开对应权限。

#### 2. 确定镜像访问方式

GHCR 包首次发布通常为私有，**代码仓库公开不代表镜像包已经公开**。在 GitHub 账号 / 仓库的 **Packages → 对应镜像 → Package settings** 检查可见性。

- 如果希望 NAS 无需登录就能拉取，可自行把镜像包设为 Public。
- 如果保持私有，在 NAS 执行 `docker login ghcr.io -u 你的GitHub用户名`，交互提示的密码填有 `read:packages` 权限的 classic PAT。不要把令牌写入 Compose；组织启用 SSO 时还需授权该令牌。通过 Container Station 拉取时，需在它的镜像仓库设置中配置对应凭据，SSH 登录凭据不一定被界面复用。

工作流不会更改仓库或镜像的可见性。有关匿名拉取、令牌与包权限，见 [GitHub Container Registry 文档](https://docs.github.com/en/packages/working-with-a-github-packages-registry/working-with-the-container-registry)。

#### 3. 在 QNAP 配置 Compose

NAS 只需要下载 `compose.ghcr.yaml` 和 `.env.example`，放在同一个应用部署目录，不需要完整源码。预先用 File Station 创建应用数据目录，并确认视频目录已经存在。

复制 `.env.example` 为 `.env`，例如：

```dotenv
AI_NFO_IMAGE=ghcr.io/your-name/ai-nfo:latest
NAS_MEDIA_PATH='/share/Multimedia/网络视频'
NAS_DATA_PATH='/share/Container/ai-nfo-data'
APP_PASSWORD='请替换为你自己的至少8位密码'
```

把镜像用户名、仓库名、共享文件夹路径和密码替换为实际值。在这两个配置文件所在目录执行：

```sh
docker compose -f compose.ghcr.yaml pull
docker compose -f compose.ghcr.yaml up -d
```

如 QNAP 仅提供旧版命令，将 `docker compose` 换成 `docker-compose`。`compose.ghcr.yaml` 是独立部署文件，不要和本地构建的 `compose.yaml` 合并使用。

随后在浏览器访问 `http://NAS地址:8787`。若 NAS 无法连接 `ghcr.io`，需要先解决镜像仓库网络可达性。

也可以把 `compose.ghcr.yaml` 内容粘贴到 **Container Station → 创建应用** 的 Compose 编辑器；如果该入口未加载同目录 `.env`，将其中 `${变量:?提示}` 逐项替换为实际值（密码和带特殊字符的路径使用 YAML 单引号）。在 YAML 中直接填写含 `$` 的密码时，按 Compose 规则将 `$` 写成 `$$`。若旧版本不支持 `bind.create_host_path`，先确认源目录已创建，再去掉该子配置。具体界面以安装的 Container Station 版本为准。

#### 4. 更新和回退

推送新代码并等待 Actions 发布成功后，在 NAS 执行：

```sh
docker compose -f compose.ghcr.yaml pull
docker compose -f compose.ghcr.yaml up -d
```

新镜像不会自动更新正在运行的容器，需要执行上述命令或在 Container Station 中重新创建容器。更新前等待批量任务结束；`/data` 和视频目录是宿主机挂载，重建容器会保留其中的数据。

需要固定版本时，将 `.env` 的 `AI_NFO_IMAGE` 改成已经发布的 `:v1.0.0`、`:sha-完整提交SHA` 或 GHCR 给出的 `@sha256:...` 摘要，再拉取并重建。开发阶段不提供跨版本数据迁移或兼容保证；切换数据结构不一致的版本时请使用新的应用数据目录。切换镜像版本不会回滚已经写出的 NFO。

### 方式二：在 NAS 本地构建镜像

### 1. 准备目录

通过 File Station 创建应用源码和应用数据目录，例如：

```text
/share/Container/ai-nfo          # 放这个项目的源码
/share/Container/ai-nfo-data     # 草稿数据库、任务记录、模型配置
/share/Multimedia/网络视频       # 已有的视频目录（示例）
```

**实际路径以你的 QNAP 为准。** 不要直接假定上述目录存在。容器中的服务需要对视频目录有读权限，保存 NFO 还需要写权限；数据目录需要读写权限。不要使用特权容器来绕过目录权限。

### 2. 首次构建镜像

将本项目上传至源码目录。随附 `compose.yaml` 是本地构建方案，需在 QNAP SSH 终端首次运行（Container Station 已安装 Docker）。

```sh
cd /share/Container/ai-nfo
cp .env.example .env
```

编辑 `.env`：填入真实存在的 `NAS_MEDIA_PATH` 和 `NAS_DATA_PATH`，设置至少 8 位 `APP_PASSWORD`。若路径包含空格，可用单引号包裹值；密码含 `$` 等字符时也使用单引号。

```dotenv
NAS_MEDIA_PATH='/share/Multimedia/网络视频'
NAS_DATA_PATH='/share/Container/ai-nfo-data'
APP_PASSWORD='请替换为你自己的密码'
```

启动：

```sh
docker compose up -d --build
```

若该版本仅提供旧版命令，使用 `docker-compose up -d --build`。首次构建需要能拉取 `golang:1.25-alpine`、`alpine:3.22` 并下载 Go 模块依赖。后端使用 Go 与纯 Go SQLite 驱动，网页资源嵌入单个可执行文件；运行镜像无需语言运行时。不同 Container Station 版本的 Compose 支持可能不同，容器镜像尚需在实际 QNAP 上构建验证。

之后打开 `http://你的NAS地址:8787`，使用 `.env` 的访问密码登录。SSH 只用于首次构建、升级和配置，日常目录扫描、模型设置、草稿与批量操作均在网页完成。

### 也可以在 Container Station 界面创建容器

先在 NAS 的项目目录构建镜像：

```sh
docker build -t ai-nfo:local .
```

在 Container Station 中从本地镜像 `ai-nfo:local` 创建容器：

| 配置 | 值 |
|---|---|
| 端口 | NAS `8787` → 容器 `8787` TCP |
| 环境变量 | `APP_PASSWORD`：自行设置至少 8 位密码 |
| Bind Mount Host Path | 视频共享文件夹 → `/media`，读写 |
| Bind Mount Host Path | 应用数据文件夹 → `/data`，读写 |
| 重启策略 | Unless stopped / 除非手动停止 |

其余环境变量镜像已设置。不要另外启动一份使用同一个 `/data` 的实例。端口已被占用时可换 NAS 端口，容器端口保持 8787。

仅使用网页无法完成“把未挂载的 NAS 目录授权给容器”；第一次需要设置挂载。网页看到的 `/media` 对应挂载的视频共享文件夹，输入 `教程/Python` 等相对路径即可选取子目录。若要访问多个共享文件夹，可分别映射到 `/media/目录A`、`/media/目录B`，避免映射整个 NAS 根目录。

## 日常使用

视频库首页顶部汇总视频总数、等待整理、待确认草稿和已保存数量。分类与搜索位于浏览区顶部；选中视频或目录后显示批量操作栏，取消选择后自动收起。统计是整个资料库的总量，列表数量随当前目录和筛选条件变化。

1. **模型设置**：选择接口类型，填写基础地址和模型 ID，保存并测试。
   - 兼容接口：程序追加 `/chat/completions`；例如某服务要求 `/v1/chat/completions`，基础地址就填写到 `/v1`。服务不支持 `response_format` 时关闭 JSON 模式。
   - Ollama：填写 `http://局域网模型主机:11434`，程序追加 `/api/chat`。容器内 `localhost` 指本容器，不是另一台电脑或 NAS 宿主机。
   - 测试连接会真实发送一次小请求，可能产生模型费用。没有内置或免费提供模型。
2. **添加视频目录**：独立视频可扫描一个大目录；剧集模式默认按完整相对目录层级组织，可一次扫描多套教程；每个包含视频的目录保存自己的剧集资料，父目录可汇总管理所有下级。若一套教程的多个季或章节需要共用剧集资料，选择「整个扫描目录作为一个剧集」。选错类型时，可选择正确类型重新扫描，更新分类和所属剧集。视频草稿保留；分类或所属剧集变化时重新识别季数、集数，已保存的条目恢复为待确认草稿，需要检查后重新保存 NFO。同类型、同剧集重新扫描保留手动修改的季数、集数。
3. **选中 → AI 生成**：同一剧集统一生成剧集资料和分集资料，JSON 同时包含 `series` 和 `episodes`，每集包含 `id、season、episode、title、plot、directors、genres、tags、notes`。文字结果先保存为草稿。默认同时启动独立的自动海报任务，直接保存图片；可取消勾选「同时异步获取并自动保存海报」。
   - 每批发送剧集名称、同剧集全部已扫描分集的完整目录层级及已有编号（包含未勾选的分集），并附上本批选中视频各自的内嵌标签、字幕和简介。未选中分集仅提供目录和编号，不读取其正文。小剧集合并请求；每批最多 20 集，序列化输入不超过 128 KiB，详细资料较长时自动拆批。完整目录与单集资料已超限时提示手动处理，不静默截断目录。
   - 默认补齐缺失的季数、集数，以及标题、简介等空白字段；已有文字和编号保留。未知导演等空数组不会单独触发生成。勾选「重新生成已有草稿」会替换分集文字，已有编号和剧集非空资料仍保留。扫描默认的第 1 季也会保留，手动清空后可让 AI 补齐。
   - 校验本批条目完整性、ID、标题、编号范围，以及与所有分集（含前面已完成批次）的编号冲突。批次校验通过后一起保存，失败不会写入半批结果；前面已完成批次保留，任务入口可重试失败项。无法可靠判断的编号返回 null，已有基础资料仍保存，提示手动补号。生成结果不会自动写入 NFO，确认后仍需保存；跨章节统一整理请选择「整个扫描目录作为一个剧集」。
4. **编辑资料**：检查简介和分集信息，可查看实际提供给 AI 的输入片段；保存草稿或预览 XML。
5. **保存 NFO**：默认跳过已有文件。勾选覆盖时直接替换原 NFO。没有草稿、无权限、集数缺失或冲突的条目会失败，其余条目继续处理。
6. **批量清除记录**：勾选视频后点击「清除所选记录」（单次最多 5000 条，包含筛选后隐藏的已选项）；视频库底部的「清空全部记录」可一次清空整个库，不受筛选和勾选影响。确认对话框会显示范围、数量和路径。清除视频记录、草稿及关联海报缓存；剧集仍有其他视频时保留剧集资料。原视频、字幕、NFO、海报文件以及模型设置、历史任务保留。重新扫描可以添加视频，但不能恢复已清除的草稿。批量任务、海报查找或截图进行中不能清除；主动清除记录不要求媒体目录在线。

关闭浏览器不影响任务。文字生成 / NFO 保存一次运行一个批次，海报队列可同时运行。取消会中止进行中的 AI / 搜索请求、重试等待和海报 FFmpeg 操作；正在写入的文件操作完成后停止。两类任务分别取消。文字生成、海报联网搜索与 AI 匹配共用模型请求并发上限，默认 1，即逐个调用接口，避免两个后台任务叠加并发。在「模型设置」调整并发数量并保存，批量任务需先完成或取消。配置会保存在应用数据目录，重启后保留。HTTP 429 也可能由额度或请求频率限制引起，降低并发不能保证消除所有 429。重启时未完成任务标记为中断，已完成结果保留；文字 / NFO 任务可点击「重试失败 / 未完成项」，海报任务可点击「重试未完成海报」。

「模型设置 → 失败自动重试次数」可设为 0–5，默认 2，即首次请求失败后最多额外重试两次；0 关闭自动重试。AI 生成、海报关键词 / 来源匹配、原生联网、Tavily / SearXNG 的网络或响应读取错误，以及 HTTP 408、429、500、502、503、504 会自动重试。等待时间从 2 秒递增至最多 30 秒；服务返回更长的 Retry-After 时遵守该时间，超过 5 分钟则停止重试。海报查找还受单次总超时限制。重试仍遵守 AI 并发上限，等待时任务卡片显示重试进度，取消任务会立即结束等待。密钥 / 权限错误、接口配置错误、无效 JSON、文件不可访问或无写权限不盲目自动重试；修正后可以手动重试。

在「批量任务」点击「重试失败 / 未完成项」会创建新的文字生成或 NFO 保存任务，沿用原任务的覆盖选项，只处理失败、取消或中断的条目，不重复成功项，也不重新启动配套海报任务。已转入重试的条目不会从同一个旧任务重复入队；再次失败时在新任务上重试。已删除的视频记录不入队。更新前的旧文字任务没有逐项结果记录，需重新选中失败视频执行。

保存失败并不会回滚已经写入的其他文件。例如剧集总览成功而单集写入失败时，总览会保留。默认跳过模式可以安全重试；覆盖模式直接替换原文件。

## 按目录层级管理剧集

在视频库点击「剧集教程」，左侧目录导航按完整相对路径保留多层结构，右侧只显示当前目录的子目录卡片和本层视频。点击目录进入，面包屑或「上一级」返回；不同路径下的同名目录互不合并。手机上可点「浏览目录」打开导航。

目录卡片上的复选框用于选择该目录及所有下级视频，点击卡片本身只进入目录。「选择整个目录」可加入当前目录全部视频；选择后使用顶部的 AI 生成、自动海报、保存 NFO 或清除所选记录。选择可跨目录、跨页保留，工具栏明确显示有多少已选项不在当前页，点击「取消选择」一次清空勾选。

默认仅显示本层视频，可勾选「同时显示子目录的视频」。在剧集视图搜索或按状态筛选时，会自动包含当前目录的全部下级；「清除筛选」恢复浏览。每页支持 25 / 50 / 100 项，「全选结果」或桌面表头复选框选择全部筛选结果（跨页）。手机列表自动排列为紧凑卡片，操作无需横向滚动。

已有剧集可直接使用目录导航，原有剧集资料归属保持不变。若要改为每个视频所在目录维护各自的剧集资料，重新扫描并选择「按相对目录层级组织」。各目录的 `tvshow.nfo`、`poster.jpg` 与单集文件存放在对应目录；仅汇总下级的中间节点不会凭空生成剧集资料。目录海报位于当前目录标题旁，点击可在页面内查看大图。

## 查找剧集和每集海报

视频列表只显示视频自身的海报；剧集中的视频只显示单集海报，剧集海报在对应目录处展示。点击小图会在该行下方展开大图，保持图片原比例，再次点击小图或「收起大图」即可收起，不打开弹窗。没有单集海报时显示「暂无海报」，后台海报任务完成后自动更新。小图按需加载，减少列表传输量。

**自动处理**：点击「AI 生成」默认附带海报任务；已经生成过资料的记录，勾选后点击「自动海报」即可单独补齐，无需重新生成文字。可在「模型设置 → 并发数量」设置 1–8 项（默认 1），整个应用按此上限处理海报（手动查找、提取和截图也共用此限额），任务会自动选择并保存，不需要逐张确认。剧集视频会同时排入每集海报及一个公共剧集海报，正在处理的相同目标不会重复入队。

处理顺序为：保留已有海报 → 提取内嵌海报 → AI 联网查找并核对来源 → 视频第 5 秒截图（失败再尝试第 0 秒）。联网只选 AI 判断为明确匹配的候选，再综合分辨率和宽高比排序；不明确匹配、接口不支持联网或搜索失败时使用截图。来源匹配依据是网页文字，并非图片视觉识别，不能保证选中的是原版官方海报。剧集的内嵌图片和兜底截图取自本批代表单集，之后可手动替换。自动任务始终保留已有图片，替换需要在「查找海报」中手动覆盖。

在「批量任务」中查看文字与海报各自的进度、取消某个任务、查看海报明细或重试未完成项。海报失败不会改变文字草稿状态。建议等海报完成再保存 NFO，让 XML 同时包含图片引用；海报任务不会修改已写好的 NFO。自动获取可能产生模型及搜索费用；未配置模型也可单独运行自动海报，使用内嵌图片或截图。

**手动调整**：以下操作仍可用于预览、更换自动结果。

打开「查找海报」会先读取当前视频文件的内嵌图片，无需 AI 或搜索服务；也可以点击「读取内嵌海报」重新提取。支持 FFmpeg 识别的附加图片流，以及 MKV 中的 JPEG / PNG / WebP 图片附件。每次最多提取 4 张，仍需选择后保存；不会改写原视频。剧集模式提取的也是当前单集的图片，请确认适合作为整个剧集的海报。没有可用图片时可继续联网查找或截图。

在视频列表点击 **查找海报**，选择“剧集海报”或“当前视频 / 本集海报”。剧集海报由该剧集所有视频共用。

1. **直接提供来源**：填写原课程 / 视频网页链接，程序提取 Open Graph、Twitter Card 或 JSON-LD 中的图片；也支持公开 JPEG / PNG / WebP 图片直链。此方式无需搜索服务或文字模型。
2. **联网搜索**：默认使用「AI 原生联网」，复用文字模型的基础地址、模型名称和 API Key，无需配置单独的搜索服务。通过 `/responses` 调用 `web_search`，适用于支持此工具的 CodexProxy / Responses 服务。只有确认接口返回已完成的搜索调用，才使用搜索来源与引用链接提取图片，不采用模型正文里猜测的网址。接口不支持时会明确报错。也可选择 Tavily（默认基础地址 `https://api.tavily.com`，需要独立搜索密钥）或 SearXNG（填写实例基础地址，需启用 JSON 输出）。不填写来源链接时，程序读取最多 5 个来源页面；选择「不使用搜索服务」则仅支持直接提供链接。
3. **AI 辅助匹配**：启用后，独立搜索服务在搜索词留空时会先用 AI 提炼关键词；原生联网由模型直接检索，使用完整相对目录、剧集名和文件名，也可手动填写搜索词。取得图片后，AI 根据来源标题、摘要判断课程及集名是否匹配，结果仅作参考，并未分析图片视觉内容。关闭辅助匹配仍可搜索和手动选择；原生联网本身仍需调用模型，可能产生模型与搜索费用。
4. **找不到合适海报**：输入秒数，点击“从本集截图”。Docker 镜像包含 FFmpeg；本机调试需要在 PATH 中安装 FFmpeg。截图失败时可尝试更早的时间点。
5. **预览并保存**：选择一张候选图片，点击“保存选中海报”。默认保留已有海报，勾选覆盖时直接替换原海报。此操作独立于文字草稿生成；没有 NFO 草稿也能先保存海报。

AI 会收到这样的目录上下文，而不只是最末级目录名：

```json
{
  "directory": "Hello Carrie自然拼读/01 Alphabet A to Z 自然拼读A-Z",
  "filename": "Alphabet A Sound Song.mp4"
}
```

目录是相对于已挂载视频根目录的路径；若希望 AI 获得上层品牌名称，应将视频根目录设置在该品牌目录的上一级或更上层。文字简介生成、剧集总览、海报关键词和来源匹配都会收到完整相对目录。

自媒体剧集缺少竖版海报时，可在「模型设置 → AI 竖版海报」配置独立的图片接口基础地址、图片模型和 API Key。图片服务需支持 Images API：有参考图调用 `/images/edits`，无可用图片时调用 `/images/generations`；请求尺寸为 `1024x1536`，要求返回 `b64_json` 图片。图片密钥独立保存，不会自动复用文字模型密钥。协议参考 [OpenAI 图片编辑文档](https://developers.openai.com/api/reference/resources/images/methods/edit) 和 [图片生成文档](https://developers.openai.com/api/reference/resources/images/methods/generate)。

- 手动操作：打开剧集海报，选择横图后点击「AI 设计竖版海报」。未选择图片时尝试当前海报、视频截图；都不可用时根据剧集名称和简介设计。生成结果先作为候选，核对标题与画面后保存；替换已有横版海报需勾选覆盖。
- 批量生成：在视频库勾选剧集目录或分集，点击工具栏「AI 竖版海报」。确认窗口按所属剧集去重显示数量，每个剧集只生成一次，不生成单集缩略图。默认保留已有海报；勾选「重新生成并覆盖已有剧集海报及配套背景图」后重新设计并替换。结果自动保存，在「批量任务」查看明细、取消或重试失败 / 未完成项；重试保留原来的生成方式和覆盖选项。与自动海报任务共享并发上限，同一剧集正在处理时不会重复入队。
- 自动任务：优先选择竖版内嵌海报；只有横图时由图片模型重新设计。配置图片模型后，无内嵌海报的剧集优先使用截图设计竖版，截图失败则根据文字设计。未配置图片模型且没有可用竖图时，任务提示配置，不把横图直接当成剧集主海报保存。已有海报仍默认保留。
- 主海报使用竖图，AI 设计的原参考图另存为 `fanart.jpg`；有原横图时背景继续使用横图。每季的 poster / fanart 分别同步，数据库也分别保留，文件丢失后可恢复。单集预览图保持原比例。无参考图时背景暂时沿用生成的海报。
- 图片设计会向所配置的图片服务发送参考图片、剧集名称、目录和简介，可能产生额外费用，单次最多等待约 5 分钟，遵守应用并发与重试设置。AI 结果需核对；返回横图、比例错误、尺寸过小或无效数据时不会保存为主海报。支持普通 Images API 响应，不接入厂商私有异步任务接口或仅返回下载链接的接口。

保存命名：剧集根目录 `poster.jpg`、每集 `视频名-thumb.jpg`、独立视频 `视频名-poster.jpg`。图片会验证并转成 JPEG。后续预览 / 保存 NFO 时加入本地图片的 `<thumb>` 引用；已有 NFO 不会自动改写，需要按原保存流程确认覆盖。外置图片命名参考 [Jellyfin 媒体图片规范](https://jellyfin.org/docs/general/server/media/shows/#metadata-images)。

每次联网查找最多返回 8 张图片，候选缓存逻辑保留 24 小时，图片总量限制为 128 MiB（清理在后续缓存写入时执行，SQLite 文件可能保留已分配空间）。超时、来源登录限制、反爬限制、仅由 JavaScript 加载图片等情况会提示跳过或自动回退截图，不能保证任意网站都能取图。原网页和图片仅访问公开网络；配置的搜索服务可以是自建内网地址。

接口参考：[Tavily Search](https://docs.tavily.com/documentation/api-reference/endpoint/search)、[SearXNG Search API](https://docs.searxng.org/dev/search_api.html)。

AI 原生联网参考：[OpenAI Web Search](https://developers.openai.com/api/docs/guides/tools-web-search)、[CodexProxy / codex2api](https://github.com/james-6-23/codex2api)。普通 Chat Completions 兼容并不代表支持原生联网；Ollama 原生接口需使用独立搜索服务。若已有配置明确选择了「不使用搜索服务」，请在模型设置中改选「AI 原生联网」并保存。搜索能找到来源也不保证 NAS 能下载该站图片，仍可能受网络或网站访问限制影响。

## NFO 输出

生成资料前会使用 FFprobe 读取文件内嵌的标题、简介、导演、作者、专辑、日期、分类等常见标签，并与完整相对目录、外置字幕 / 简介一起提供给 AI；不会发送全部技术标签。每集标签和外置资料按原始 ID 分开提供，剧集总览依据完整目录，不能将某一集的标签当作整个剧集的资料。标签可能不准确，仍需核对草稿。

不使用 AI 时，可在「编辑资料」点击「读取内嵌资料」，补充默认标题和空白的简介、分类、导演，再保存草稿。已编辑的字段保留；原始标签及读取提示可在「查看将发送给 AI 的资料」中查看。只从明确的 `director` 内嵌标签补充当前视频导演，不把作者、讲师、频道或上传者自动当成导演。作者和日期仍只作为参考输入。

内嵌资料按需读取，不会拖慢目录扫描。文件没有标签时继续使用已有输入；缺少 FFprobe、读取失败或超时时会提示并保留外置资料生成流程。本机调试需安装包含 `ffmpeg` 和 `ffprobe` 的 FFmpeg 工具包，Docker 镜像已包含。读取和截图均限制为本地媒体，不会执行标签里的路径或指令。参考 [FFprobe 文档](https://ffmpeg.org/ffprobe.html) 和 [FFmpeg 附件提取文档](https://ffmpeg.org/ffmpeg.html#Main-options)。

独立视频使用 `<movie>`：

```text
摄影技巧.mp4
摄影技巧.nfo
```

剧集使用 `<tvshow>` + `<episodedetails>`：

```text
Python 教程/
  tvshow.nfo
  Season 01/
    Python S01E01 - 环境准备.mp4
    Python S01E01 - 环境准备.nfo
    Python S01E02 - 变量.mp4
    Python S01E02 - 变量.nfo
```

使用本地 `uniqueid`，不伪造 TMDb / IMDb 等 ID。XML 由程序生成和转义。草稿支持导演列表，可由 AI 根据明确资料提取，也可在编辑页面手动填写，多人用逗号分隔。保存 NFO 时每位导演对应一个 `<director>`，没有导演则省略。独立视频、单集和剧集各自保存导演，剧集导演不自动继承到每集。已有草稿需手动补充或重新生成；已有 NFO 需选择覆盖保存才会更新（直接覆盖原文件）。日期、评分和作者暂无输出字段。

这是 **Kodi 风格的通用 XML**，尚未针对某个用户选定媒体库做实机验证。各播放器的导入设置、命名规则和字段支持不同。剧集通常仍需 `S01E01` 等命名让媒体库正确发现；本工具不会自动改名，仅有 NFO 不保证任意文件名都能入库。多集合并文件目前不支持；同目录同名不同扩展名视频会共用 NFO，因此先提示冲突。

## 数据与当前边界

- 密钥以权限 `0600` 的 JSON 保存在 `/data/settings.json`，没有加密；网页仅收到“是否已设置”，不会回显密钥。保护应用数据目录及其备份。
- 远程模型会收到选中视频的文件名、完整相对目录和截取的字幕 / 简介。单视频合计最多 24000 字符，单个资料文件最多读取 160000 字节；长资料不是全文摘要，生成内容需核对。
- 不会上传视频；不处理内嵌字幕或自动转写。海报功能按需请求来源网页、下载图片或在 NAS 本地截图；AI 竖版设计还会将参考图和剧集资料发送到独立配置的图片模型。文字简介没有外置资料时仍是保守的文件名整理。
- 已有 NFO 会被检测和保护，**不会自动导入为工作台草稿**。手动选择覆盖会用工作台当前字段重新生成 NFO，原有其他字段不会迁移。
- 视频库底部提供“清理不可访问视频”入口：先列出整个视频库的待清理记录，确认后移除记录和草稿（每次最多 5000 条），不删除视频、字幕或 NFO。可用“文件不可访问”筛选查看这些条目。确认时会重新检查，已恢复访问的文件自动跳过；批量任务运行中或视频根目录不可访问时不能清理。数据目录为单个视频根目录服务，换挂载内容时请使用不同的数据目录，避免旧路径草稿被复用。
- 默认局域网使用。若需外网访问，在 QNAP 反向代理配置 HTTPS，勿直接把明文 HTTP 端口开放至公网。
- 自动转写、NFO 导入合并、批量重命名和媒体库远程刷新尚未实现。

## 本机开发与验证

Go 1.25 或更新版本；首次构建会下载 `go.mod` 中的依赖。默认仅绑定本机地址；对局域网监听必须设置至少 8 位访问密码。

```sh
MEDIA_ROOT=/实际的视频目录 DATA_DIR=/实际的数据目录 go run .
```

```sh
go test -race ./...
go vet ./...
go build -o ai-nfo .
node --check static/app.js
node --check static/covers.js
```

测试使用临时目录和本地假模型 HTTP 服务，验证目录边界、真实协议请求、草稿到 XML 的文件写入、跳过和覆盖、冲突、任务取消与中断恢复、身份验证及跨站请求拒绝。假模型只用于测试，不会在产品中伪装成真实生成。

### VS Code 断点调试

1. 用 VS Code 打开项目根目录，安装推荐的 **Go** 扩展（`golang.go`），确保终端可以执行 `go version`。
2. 在项目根目录创建 `media` 文件夹，放入用于测试的视频及字幕 / 简介。`data` 目录由程序启动时自动创建；这两个目录都已被 Git 忽略。
3. 在“运行和调试”中选择 **AI NFO：本地启动**，按 `F5`。首次启动若提示安装 Delve，按提示安装 `dlv` 后再启动。
4. 浏览器打开 `http://127.0.0.1:8787`，可在 Go 代码中设置断点。默认仅监听本机、无需登录；AI 接口在网页设置。

配置位于 `.vscode/launch.json`。修改 `MEDIA_ROOT` 可指定其他本地目录，修改 `PORT` 可避开端口冲突；如需测试登录，设置其中的 `APP_PASSWORD`。该配置直接提供环境变量，不读取部署用的 `.env` 文件。

选择 **AI NFO：调试测试** 可调试整个包的测试，或使用 Go 扩展在具体测试函数上方提供的调试入口。测试内有较短的等待时间，长时间停在异步任务断点上可能触发测试超时。网页资源嵌入 Go 程序，修改 HTML / CSS / JavaScript 后需重新启动调试并刷新浏览器。

调试方式参见 [VS Code Go 官方文档](https://github.com/golang/vscode-go/blob/master/docs/debugging.md)。
